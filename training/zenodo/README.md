# Pie Tactic-Prediction Model (LoRA) — reproducible artifact

A fine-tuned model that predicts the next proof tactic for **Pie**, a
dependently-typed language based on *The Little Typer*. It is a QLoRA adapter on
top of `Qwen2.5-Coder-7B-Instruct`, served over HTTP for the Pie proof editor.

This bundle is **self-contained and offline**: it ships the LoRA adapter, the
exact 4-bit base model, the serving/evaluation code, pinned dependency specs,
and a holdout test set. No network access is needed at run time.

---

## 1. Hardware requirements (read first)

The model runs in **4-bit (bitsandbytes NF4)** precision, which requires an
**NVIDIA CUDA GPU**. There is **no CPU / Apple-Silicon / AMD fallback** — on
unsupported hardware `preflight.py` prints a clear message and exits without
attempting to load the model.

| Requirement | Minimum | Used for published results |
|---|---|---|
| GPU | NVIDIA, compute capability ≥ 7.0 | RTX 4080 Laptop (CC 8.9) |
| VRAM | ≥ 7 GB (footprint ~6.5 GB) | 12 GB |
| CUDA runtime | 12.1 (pinned `torch` is `cu121`) | 12.1 |
| OS | Linux or Windows | Windows 11 |
| Python | 3.11.x | 3.11.15 |

> Do **not** use Ollama/GGUF quantization for this model: Q4_K_M loses the
> `go-Left` vs `go-Right` distinction. The PEFT adapter path here is the only
> serving method that reproduces the published accuracy.

## 3. Setup

```bash
conda env create -f environment.yml
conda activate pie-tactic-model
# or, into an existing Python 3.11 env:
#   python -m pip install -r requirements-lock.txt
```

## 4. Verify the artifact (recommended)

Runs the hardware preflight, then evaluates the model on the holdout.

```bash
./verify.sh          # Linux / macOS / Git-Bash
./verify.ps1         # Windows PowerShell
```

**Expected:** preflight `OK`, then **13/13 exact-match (100%)** on the holdout.
On unsupported hardware you instead get a `HARDWARE NOT SUPPORTED` report and a
non-zero exit — nothing is loaded.

## 5. Serve

```bash
./run.sh             # serve on :8000  (PORT=9000 ./run.sh to change)
./run.ps1            # Windows
```

First request is slow (~25–30 s, model load + CUDA warmup); subsequent
predictions are ~0.5–1.5 s.

### API

`POST http://localhost:8000/predict`

```json
{
  "goal": "(Even (add1 (add1 0)))",
  "globalContext": [{"name": "Even", "type": "(Π (x Nat) U)"}],
  "localContext": []
}
```

Response:

```json
{
  "tactic": "exists 1 half",
  "raw_output": "exists 1 half",
  "tactic_head": "exists",
  "category": "constructor",
  "elapsed_ms": 640.0
}
```

`GET /health` returns `{status, model, adapter}` once the model is loaded.

## 6. How it loads

`serve.py` → `LocalPredictor` (in `evaluate_offline.py`):
1. reads `adapter/adapter_config.json`;
2. loads the base model from `base-model/` (via `PIE_BASE_MODEL`, set by the
   run/verify scripts) with a 4-bit `BitsAndBytesConfig` and `device_map="auto"`;
3. attaches the LoRA adapter with `peft.PeftModel.from_pretrained`;
4. generates greedily (`temperature=0`, deterministic) up to 128 new tokens.

`HF_HUB_OFFLINE=1` / `TRANSFORMERS_OFFLINE=1` are set so nothing touches the
network.
